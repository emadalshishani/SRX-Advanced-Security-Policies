# SRX Advanced Security Policies

A hands-on Juniper SRX lab repository focused on security policy design, application matching, traffic enforcement, and policy-log verification.

The repository is organized as a growing collection of practical security-policy experiments. Each experiment documents the configuration applied to the SRX, the traffic generated by the test host, and the evidence collected from the firewall.

## Project objectives

- Build and test Juniper SRX security policies using real traffic from an Ubuntu endpoint.
- Use Address Book objects to identify traffic sources instead of hard-coding host IP addresses in every policy.
- Match traffic by Junos predefined applications, including DNS over UDP, DNS over TCP, and ICMP.
- Apply policy actions and observe their effect on live traffic.
- Enable and inspect local session logs to verify which policy handled each flow.
- Keep configuration, test results, and topology documentation together for repeatability.

## Current experiment

### Application-Based Security Policy Matching and Logging

A Global Address Book object identifies the Ubuntu endpoint:

```bash
set security address-book global address ubuntu-user-ip 192.168.30.2/32
```

A dedicated policy is configured from `internal` to `branch`:

- **Source address:** `ubuntu-user-ip`
- **Destination address:** `any`
- **Applications:** `junos-dns-udp` and `junos-dns-tcp`
- **Action:** `deny`
- **Logging:** `session-init` and `session-close`

The ICMP application `junos-ping` was added temporarily for a separate test and then rolled back. It is not part of the intended DNS-filtering configuration.

### Test coverage and observed results

| Test | Policy match | Observed result | Verification |
|---|---|---|---|
| DNS over UDP | `junos-dns-udp` | DNS requests were denied | `RT_FLOW_SESSION_DENY` log entries |
| DNS over TCP | `junos-dns-tcp` | `curl` could not resolve `google.com` | `RT_FLOW_SESSION_DENY` log entries |
| ICMP Echo Request | Temporary `junos-ping` match | Ping traffic was denied while the match was active | ICMP `RT_FLOW_SESSION_DENY` log entries |
| ICMP during DNS-only test | No ICMP match in the test policy | Ping replies were received | Ubuntu ping output |

The firewall logs identify the policy `internal-branch_ubuntu-user-test` and show the reason `Denied by policy`. This confirms that the matching traffic was denied by that policy.

## Local log verification

The tests were verified on the SRX using the local `messages` log:

```bash
run show log messages | match RT_FLOW_SESSION | match udp
run show log messages | match RT_FLOW_SESSION | match tcp
run show log messages | match RT_FLOW_SESSION | match icmp
```

The key log identifier is `RT_FLOW_SESSION_DENY`. The records include the source and destination, application or protocol information, the policy name, and the denial reason.

## Scope and next experiments

This repository is intended to grow as additional SRX policy topics are labbed and verified. The current experiment establishes the baseline for application-based matching and local logging. Further experiments can be documented separately as they are configured and tested, such as Address Sets, custom applications, policy ordering, scheduling, and more advanced policy controls.

Only tested behavior is marked as a result. Planned topics will be added after their configurations and verification evidence are available.
